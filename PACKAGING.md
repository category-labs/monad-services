# Packaging monad-services

`monad-services` owns the build and Debian-package instructions for the services
that have moved out of `monad-bft`.  The initial package contains these binaries:

- `monad-archiver`
- `monad-archive-checker`
- `monad-indexer`
- `monad-block-writer`

The pinned `monad-execution` submodule is part of the source checkout.  The build
initializes it automatically; to do it explicitly (for example, before an offline
build), run:

```sh
git submodule update --init --recursive
```

The package installs the native shared objects generated by the `monad-triedb`
and execution bindings under `/usr/local/lib`; its `postinst` refreshes the dynamic
linker cache.  This mirrors the relevant runtime behavior of the BFT package
without bundling BFT node binaries.

Build directly on a Debian-compatible host with `make deb`.  The result is placed
in `dist/` by default.  Supply a release version explicitly with
`make deb PACKAGE_VERSION=1.2.3`.

For a reproducible Linux build on any developer machine, use `make deb-container`.
It selects Podman when present, otherwise Docker, and copies the `.deb` from the
resulting container image into `dist/`.
The Jenkins job should only perform a recursive checkout and invoke this target;
publication, credentials, and retention remain Jenkins responsibilities.

The systemd units deliberately take their arguments from `/home/monad/.env` only;
service-specific command-line options should be introduced alongside their Rust
CLI changes rather than duplicated in Jenkins.

The repository layout follows `monad-bft`: static package contents live in
`debian/`, the OCI-neutral build definition lives in `containers/Containerfile`,
and build entry points live in `scripts/`.
